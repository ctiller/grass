# HTTP/2 implementation-constraint inventory

Status: adversarial design inventory for Spike 4 and the future gRPC fixture.
This document does not implement a library and is not independent semantic
authority. The authoritative constraint family is generated by capturing the
precious `SpecProcess`; this document is its review projection.

## 1. Authority, notation, and status

Protocol authority is [RFC 9113](https://www.rfc-editor.org/rfc/rfc9113.html)
and [RFC 7541](https://www.rfc-editor.org/rfc/rfc7541.html). Repository ownership
is divided as follows:

- [GRAMMAR.md](GRAMMAR.md) owns byte languages, exact prefix parsing, writers,
  and normalization;
- [PROCESS.md](PROCESS.md) owns channels, process order, partial I/O, custody,
  cancellation composition, and resource flux;
- [SEMANTICS.md](SEMANTICS.md) owns requirement origin and observational
  refinement;
- [RESOURCES.md](RESOURCES.md) owns semantic budgets, realization envelopes,
  axes, and bounds;
- [MEMORY_MODEL.md](MEMORY_MODEL.md) and [OBLIGATIONS.md](OBLIGATIONS.md) own
  physical authority, races, provenance, loans, and terminal dispositions;
- [PLATFORM_ABI.md](PLATFORM_ABI.md) owns Win32 provider and ABI realization;
- [ASSEMBLY_CONSTRUCTION.md](ASSEMBLY_CONSTRUCTION.md) owns typed CFGs and exact
  fragment expansion;
- [VERIFIED_PROGRAM.md](VERIFIED_PROGRAM.md) owns requirement closure and the
  emitted-artifact connection;
- [SPIKE_4.md](SPIKE_4.md) and [WEB_SERVER.md](WEB_SERVER.md) own the current
  fixture and acceptance claims.

Every key below is a stable key from the staged obligation family derived from
the selected HTTP/2 package. Portable keys are emitted by the specification;
projection, provider, machine, and artifact keys are derived later and retain a
total origin path to the earlier stage. They are mechanically indexable as text
and as Lean names. Status means:

- **present**: the current fixture contains a proposition and a connected named
  witness route into `serverVerified`;
- **disconnected**: a suitable-sounding declaration or constructor exists, but
  exact origin, coverage, proof body, or connection to emitted bytes is absent;
- **missing**: no implementation-facing theorem shape is currently shown.

`∀ run ∈ Runs(I)` quantifies every execution admitted by implementation `I`,
including every permitted scheduler choice and provider result. `refinesₒ`
means trace refinement through the specification-selected observation filter.
`parseₚ` is prefix parsing. `WF`, `Inv`, `Own`, `Obl`, and `Res` denote protocol
well-formedness, invariant, ownership, obligation, and resource ledgers.

## 2. Constraint-origin law

The inventory is valid only if it is extracted from the selected protocol
package and its staged lowering. It may not make target choices precious:

```lean
structure Http2ConstraintIndex
    (package : Http2.Server.Package R)
    (obligations : StagedProtocolObligations package) where
  portable : DemandAuditProjection obligations.portable
  projection : DemandAuditProjection obligations.projection
  provider : DemandAuditProjection obligations.provider
  machine : DemandAuditProjection obligations.machine
  artifact : DemandAuditProjection obligations.artifact
  entries := portable ++ projection ++ provider ++ machine ++ artifact
  keysExact : entries.keys = obligations.disjointUnion.keys
  statementsExact : ∀ key ∈ entries.keys,
    entries[key].demand = obligations.disjointUnion[key]
  dependenciesExact : DependencyEdges entries =
    obligations.disjointUnion.dependencyEdges
  originExact : EveryNonPortableEntryHasOnePriorStageOrigin entries obligations
  noDuplicateAuthority : EveryEntryIsAuditProjectionOfStagedDemand entries obligations
```

Adding gRPC refines or extends the captured suite and regenerates this index.
Reviewers may add a missing row here only by first adding or identifying its
source or derived demand at its proper stage. A row cannot strengthen the
program by itself. Requirement closure is a meta-theorem over the resulting
union and is deliberately not an indexed row.

## 9. Umbrella certificate and refinement theorem

The umbrella object is indexed by the captured spec and contains implementations
of its demands, not a separately authored list of HTTP/2 facts:

```lean
structure CompleteHttp2ConstraintSet
    (package : Http2.Server.Package R)
    (obligations : StagedProtocolObligations package)
    (index : Http2ConstraintIndex package obligations)
    (implementation : Http2Implementation) where
  witness : (key : obligations.disjointUnion.Key) ->
    ImplementationWitness implementation obligations.disjointUnion[key]
  phaseOwnerExact : ∀ key member,
    witness key member |>.phase = index.entries[key].phase
  dependencyClosure : ∀ key member,
    EveryDependencyWitnessUsesSameImplementation
      implementation index.entries[key] (witness key member)
  sourceIdentity : AllMachineWitnessesReferTo implementation.rawProgram
  providerIdentity : AllProviderWitnessesReferTo implementation.providerEnv
  artifactIdentity : AllArtifactWitnessesReferTo implementation.artifact
  noExtraAssumptions : WitnessPremisesEqualStagedPremises obligations witness
```

The desired library theorem is a fold over the captured requirement dependency
graph. Grammar theorems feed protocol transitions; process/channel theorems
lift transitions to histories; resource, memory, concurrency, obligation and
provider theorems restrict every concrete step; typed CFG and fragment theorems
simulate the machine; artifact theorems identify the loaded bytes with that same
machine program.

```lean
theorem CompleteHttp2ConstraintSet.implies_refinement
    (complete : CompleteHttp2ConstraintSet
      package obligations index implementation) :
    (∀ load ∈ implementation.artifact.admissibleLoads,
      LoadedRuns load ⊆ implementation.machineRuns) ∧
    (implementation.machineRuns refinesₒ package.specProcess.denotation) ∧
    EveryLoadedRunSafeProgressingAndObligationCorrect
      implementation.artifact package.specProcess := by
  exact StagedRequirementDependencyGraph.fold
    obligations.disjointUnion
    complete.witness
    complete.dependencyClosure
    complete.sourceIdentity
    complete.providerIdentity
    complete.artifactIdentity
    complete.noExtraAssumptions
```

`VerifiedProgram` consumes this result and checks the disjoint-union coverage,
each stage origin, and `package.captureExact`. Closure is the meta-theorem being
constructed, not a member of the family it closes. A manually assembled record
whose keys merely resemble this document is rejected.

## 10. gRPC extension seam

A later gRPC suite should be a refinement/extension of the HTTP/2 suite, not a
fork. It retains every applicable `h2.*` key and adds at least:

- `grpc.grammar.message`: 1-byte compressed flag, 4-byte big-endian length,
  exact incremental message-body partition, and codec round trips;
- `grpc.model.metadata`: required request/response fields, binary metadata,
  trailers, and `grpc-status`/`grpc-message` semantics;
- `grpc.model.rpc_lifecycle`: unary and selected streaming RPC state machines
  refining one HTTP/2 stream each;
- `grpc.flow.pipeline`: HTTP/2 credit/backpressure composed with bounded message
  decoding, application queues, and response production;
- `grpc.cancel.deadline`: gRPC timeout/status mapped to the existing addressed
  stream cancellation and exact suffix disposition;
- `grpc.resource.message`: decoded-message, compression, method state, and work
  axes added to the existing per-stream subgraph bound;
- `grpc.obligation.application`: application/database obligations remain distinct
  from transport obligations and obey terminal adoption policy; and
- `grpc.artifact.closure`: all added handlers/codecs are tied to the same provider,
  raw program, and artifact identities.

The extension theorem shape is:

```lean
theorem grpc_extends_http2
    (grpc : CompleteGrpcConstraintSet grpcSpec grpcImpl) :
    RestrictRequirements grpcSpec `h2 = baseHttp2Spec.requirements ∧
    ProjectGrpcObservations grpcImpl refinesₒ baseHttp2Spec.denotation
```

This seam allows the HTTP/2 transport proof, HPACK state, partial-I/O proof,
flow-control conservation, provider model, and artifact chain to remain stable
while gRPC adds message and application semantics.

## 11. Current coverage verdict

The current corpus does not yet show an implementation-facing theorem for every
captured demand. It has strong intended names for stream state, HPACK order,
flow conservation, cancellation, resources, and artifact connection, but most
are disconnected from exact requirement origin or are populated by undeclared
library witnesses. DATA and HEADERS now have selected normalization bodies, but
their raw expansions, local theorems, and debit/HPACK connections remain
disconnected. The clearest remaining missing or disconnected constraints are:

- DATA padding-to-flow-credit and HEADERS PADDED/PRIORITY-to-HPACK connection
  theorems over the selected bodies;
- HPACK table-size-update position;
- one generated exhaustive RFC error-code/scope matrix;
- extension-frame stuttering refinement;
- complete memory-access, race, stack/ABI and WinSock-provider coverage;
- total typed CFG contracts and locally checked raw fragment expansions; and
- exact captured-key coverage in `VerifiedProgram.requirementClosure`.

These are design gaps, not permission to hand-write a second checklist into
`serverVerified`. Each must become a captured keyed demand with a reusable
implementation theorem or a visible residual goal.
